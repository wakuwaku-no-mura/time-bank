# 静的HTML/CSS開発時の注意点と不具合対策

## 1. 相対パスの計算

複数階層の構造をとる場合、静的ファイル（CSSや画像など）への相対パスがずれないよう、階層の深さに応じて `../` の数を入念に計算すること。
- ルート直下のファイルから `static/` へのパス: `static/...`
- `/activities/index.html` (1階層下) から: `../static/...`
- `/activities/2026-05-10-schongarten-cleanup/index.html` (2階層下) から: `../../static/...`
- 3階層深くない限り、`../../../` は使用しない。

## 2. ローカル確認時のディレクトリリスティング防止

Webサーバーを介さずブラウザで `file://` スキームとして直接ローカルHTMLファイルを開く場合、リンク先がフォルダ名（`/` で終わるパス）になっていると、ブラウザはフォルダ一覧（ディレクトリリスティング）を返してしまう。
- ローカルテスト時の動作を担保するため、リンク先のパスは `activities/index.html` のように明示的に `index.html` まで含めること。

## 3. ヘッダーロゴの文字制限

`index.html` のヘッダーの左側タイトルエリア（`.title`）は幅が狭く固定されている（特にモバイル幅では `190px`）。ロゴの文字を増やすと改行が発生してレイアウトが崩れる。
- ロゴのテキストは「じかんぎんこう」から変更しないこと。戻り導線を設ける場合は、テキストを書き換えるのではなく `href` 属性をトップページに対応させる（`../index.html#nature` 等）ことで実現すること。

## 4. スクロールアニメーション (`scroll_up`等) の適用位置

ページを開いた際に最初に見える領域（ファーストビュー）のコンテンツに `scroll_up` などのアニメーション用クラスを付与すると、スクロールするまで非表示（透明）になってしまう。
- ファーストビューに入る主要コンテンツには `scroll_up` 等のクラスを付与せず、最初から不透明で表示されるようにすること。
